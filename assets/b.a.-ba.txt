Directives Docker Compose

- services : Section racine d'un fichier Compose qui définit chaque conteneur/service de l'application (ex. routeurs, shards, serveurs de config).
- image : Image Docker utilisée pour créer le conteneur, téléchargée depuis un registre si absente localement (ex. mongo:7).
- build : Construit une image à partir d'un Dockerfile au lieu d'utiliser une image existante. Peut préciser le contexte et le fichier (context, dockerfile).
- command : Surcharge la commande par défaut du conteneur (CMD/ENTRYPOINT selon usage). Ex. lancer mongod/mongos avec des options.
- container_name : Nom fixe attribué au conteneur (sinon Docker Compose en génère un). Utile pour cibler un conteneur par son nom.
- volumes : Monte des volumes nommés ou des chemins hôte dans le conteneur pour persister les données ou partager des fichiers. Ex. ./python:/app ou mongo-data:/data/db.
- ports : Publie des ports du conteneur vers la machine hôte au format hôte:conteneur. Ex. "27017:27017" expose un routeur sur l'hôte.
- networks : Réseaux virtuels auxquels le service se raccorde. Les conteneurs d'un même réseau se résolvent et communiquent par nom de service/conteneur.
- depends_on : Définit des dépendances de démarrage entre services. Peut attendre qu'un service soit démarré ou qu'il ait terminé avec succès (condition: service_completed_successfully).
- environment : Variables d'environnement injectées dans le conteneur (ex. URI, paramètres applicatifs).
- restart : Politique de redémarrage du conteneur : "no", always, unless-stopped, on-failure. Permet de relancer un service après arrêt/crash selon le besoin.
- develop : Section de développement (Compose Watch) permettant de synchroniser des fichiers, reconstruire ou relancer automatiquement lors de modifications en dev.
- include : Permet d'inclure d'autres fichiers Compose dans le projet pour composer/organiser une configuration en plusieurs fichiers.

Options MongoDB (moteur mongod/mongos)

- replSet : Nom du replica set (ex. --replSet rs_a). Active la réplication (primary/secondary) nécessaire au sharding et à la haute disponibilité.
- shardsvr : Indique que l'instance mongod est un membre de shard dans un cluster shardé (écoute par défaut sur le port shard, ex. 27018).
- bind_ip_all : Fait écouter le serveur sur toutes les interfaces réseau (0.0.0.0) afin qu'il soit joignable depuis les autres conteneurs du réseau.

Healthcheck (vérification de santé)

- healthcheck : Décrit comment Docker vérifie que le conteneur est réellement prêt/fonctionnel (au-delà du simple démarrage).
- test : Commande exécutée pour le contrôle de santé (ex. ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]).
- interval : Fréquence d'exécution du test de santé (ex. 10s).
- timeout : Durée maximale accordée à l'exécution du test avant de le considérer en échec (ex. 5s).
